Generated by `EventOpcodeCensusTests.Census` from the retail event DATs; do not edit by hand. Regenerate with
`GORDIAN_WRITE_DOCS=1 dotnet test tests/Gordian.Core.Tests --filter EventOpcodeCensusTests` on a machine with the game installed.

Scope: 296 zones with event DATs, 209,144 event entries. Each entry is walked from its start by the opcode length table (`EventOpcodeTable`) up to the next entry's offset, so the counts are lower bounds: code reached only by a jump past that offset, and the rest of an entry after an opcode of unknown length, are not counted. The other way, script tables (runs of 16-bit work references, `NN 80`) that sit after an end inside an entry's range are walked as code, which inflates the opcodes that look like table bytes (0x6D, 0xA6, 0xB2, 0xCB, 0xD7 and part of 0x80 are mostly such data) and makes every sub-case 0x80 row table data. *Events* is the number of entries that use the opcode at least once. What each opcode does and what GordianXI does with it is in [opcodes.md](opcodes.md).
