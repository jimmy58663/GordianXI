## Launch

`MainWindowViewModel.LaunchSelected` keeps two paths for LandSandBoat profiles:

- **Login mode (profile editor):** a radio choice, "Character Select screen" or "Auto-Login" (`AccountProfile.LoginMode`, saved in the profile JSON). Auto-Login needs a Character Name or a Character Slot 1-16; saving without one is refused. A profile saved before the choice existed has no `LoginMode` and keeps its behaviour (`EffectiveLoginMode`): Auto-Login when it names a character, character select otherwise. Auto-Login with no character falls back to character select. The Character Name and Character Slot fields show only while Auto-Login is chosen (character select picks the character on screen); hiding them keeps their values, which the profile still saves and which return when Auto-Login is picked again. Slot is a drop-down, "Not set (use the name)" then 1-16; its selected index is the stored `CharacterSlot` (0 = not set), so existing profiles load unchanged.
- **Auto-Login (the fast path, unchanged):** logs straight in as the named character (`LsbLoginClient.LoginAndSelectAsync`, now running over `LsbLobbySession`).
- **Character select (retail behaviour):** (`UsesCharacterSelect`) logs in, opens an `LsbLobbySession` and a `LobbyController`, and shows the lobby in the primary viewport window (`ViewportWindowManager.ShowLobby`). Only one lobby is open at a time; a second character-select profile is skipped with a status message. The chosen character's ticket starts the game session through the same code as Auto-Login (`StartLsbSessionAsync`); the lobby leaves the viewport once the session's tab is registered. Decline on the licence page, Back on the title menu, or a lost lobby connection closes the lobby and disconnects.
- **Log Out returns to the title menu, in the same window:** a session that came through character select reopens it when the server ends the session with S2C 0x00B state Logout (`/logout` or the menu's Log Out; `SessionNetworkManager.LoggedOut`, raised before the session disconnects). The handler first calls `ViewportWindowManager.BeginLobbyReturn`, so when the disconnect removes the tab the viewport window stays open and shows black (`ViewportViewModel.IsReturningToLobby` -> `VeldridViewportControl.HoldBlack`). The launcher then logs in to the lobby servers again underneath (a new xi_data / xi_view session: LSB's map session is gone after a Log Out, so the old lobby connection cannot be reused), shows the title menu in that window (without the licence page), and the lobby fades in from black over `LobbyFadeInSeconds` (0.5 s; every lobby appearance fades in). `EndLobbyReturn` then lets the window close again if the lobby could not be shown (the error goes to the status line). A Shut Down (state PolExit), a dropped connection or an Auto-Login session ends as before. Before round 3 the disconnect closed the viewport window (the registry unregistered the session on Disconnected, the window had no tab and no lobby) and the lobby opened a new window and graphics device. **Unverified:** that LSB answers Log Out with state 1 and Shut Down with 5; retail's fade timings.

The retail bootloader / `ProxyStager` path is not touched: the retail client draws its own lobby.

## What the lobby is made of

Research 2026-09-28 ([#31](https://github.com/jimmy58663/GordianXI/issues/31)), corrected and extended 2026-10-04 by compositing every lobby menu (`GORDIAN_UI_DUMP_LOBBY=1` with `GORDIAN_UI_DUMP_MENUS` / `GORDIAN_UI_DUMP_SCREENS` in `UiResourceRealDataTests.DumpMenuComposites`). Sources: xi-tools `docs/title/` and `docs/dats/ROM_0_23.md`, checked against the retail install.

- **Title background: `ROM/0/23.DAT`** (magic `titl`, 73,872 bytes). A live 3D fly-through of real zones, not an image; the file holds no geometry or textures of its own. Sections: 317 `0x06` camera routes, 24 `0x07` routines, 3 `0x2F` environments; 22 zone segments, each with its own camera family and per-segment weather and fog. Segment 12 always plays first; later segments are picked by a rule that is not in the file. **Not drawn yet:** the lobby shows its backgrounds over black.
- **Lobby UI: `ROM/119/50.DAT`** (magic `lobb`; English. JP `ROM/91/16`, DE `ROM/176/74`, FR `ROM/178/13` per xi-tools), loaded by `UiResourceLibrary.LoadLobby` ahead of the in-game menu DATs (whose `windowps` labels, fonts and window skin the lobby menus use). Its 9 `0x20` textures are `chmkfnt`, `titlwin` (the title art), `abxy360`, `otp`, `ex1us`/`ex2us`/`ex5us`, `b1n` (the pill buttons) and `wardrb`. Its 56 menus:
  - **Title:** `loby1win` (1024 x 768: the FINAL FANTASY XI art and the copyright line) and `loby2win` (Select Character / Create Character / Delete Character / Config / Back, ButtonIds 1, 2, 3, 5, 4 top to bottom, authored at x 354 in the same 1024 x 768 space). Each button's kind-4 image is its highlighted look (blue caption), drawn on the selected button.
  - **Character list:** `bgnamese` (640 x 480 backdrop with a small logo at 32,32) and `dbnamese` (16 buttons, 128 x 16 bars in two columns of eight at x 304 and 480 from y 242, 18 px apart; ButtonId = slot; the frame image draws all 16 dim bars, the buttons' image #77 is the light bar of the selected slot). `acnamese` (111 x 12, top right) is empty art. `chfwin` / `chf360` ("Options — + : Settings Management", Load / Save) and `chswin` / `chs360` ("Options — File Slot": Server, Slot A-D) are the settings-file windows the + key opens on the list; **not built.**
  - **Correction to the 2026-09-28 notes:** `lobycwin` / `lobyc360` are the lobby **Config** window (Title Music, Title Music and Sound Effects Volume, Logout Destination, Background Aspect Ratio, Gamepad Settings), not the character list, and `chswin` / `chs360` are not main-strip variants.
  - **Creation:** `chmkrace` (8 races), `chmkface` (8 faces), `chmkhair` (A / B), `chmksize` (3 sizes), `chmkjobs` (6 jobs), `chmktown` (3 nations), each 112 px wide at (32, 32) with red page arrows (frames #25 / #26) outside its edges; their labels are in-game `windowps` images (races 112-119, faces 174-181, hair 182-183, sizes 184-186, jobs 156-161, nations 584-586). `chmkname` / `chmkserv` / `chmkpass` are the "Name", "World" and "Gold World Pass" fields (200 x 26 at y 32, 60, 88), `worldsel` the world list (14 rows of 184 x 16), `race1`-`race8` the large race captions and `nation1`-`nation3` the flags (top right). `hn*` are the PlayOnline handle screens, not used.
  - **Prompts:** `ptc5ok` (OK), `ptc6yesn` (Yes / No), `ptc9dele` (Delete / Cancel, with the warning sign as button 3), `ptc7vup` / `ptc8lice` (version-up and licence), `ptc2warn` (no buttons: used here for the status line while a request runs), `ptc1prog` / `ptc10che` / `ptc3bar*` / `ptc4bar*` (patch and file-check progress, not needed with LSB). They are 512 wide with their origin at the layout's centre column (x 256, parts from -256).
  - **Help bar:** `lobyhelp` (one 640 x 26 bar, image #2 at -256..384, 155..181 from the frame at (256, 224), bottom-left anchored).
  - **`lobbyps2` = `lobbywin`.** The creation, name and prompt menus name their images in a group `lobbyps2` that the PC DAT does not carry; `lobbywin` has the same images at the same indices (#74 "Name—", #75 "World—", #95 the yes/no frame, #115 / #116 Delete / Cancel, #117 the warning sign, #3-#10 the race captions, #133-#135 the nation flags), so `LoadLobby` aliases it. **Beyond xi-tools.**
  - Other `lobbywin` images: #86-#93 small expansion icons, #141 / #157 / #159 / #172-#180 expansion banners, #137 / #138 the creation stats panel ("Name: / Main Job: / Support Job: / STR ... CHR"), #139 / #140 "Naming way: Press the + Key to generate a random name", #183 Config, #189 / #190 Title Screen / Select Character, #227-#232 wardrobe 3-8 icons, #235 the race-change star.
- **Captions are sprites, not text.** Each `loby2win` button references a label image in `lobbywin` (Select Character = kind 0 image 126, its highlighted look kind 4 image 127; Create 128/129, Delete 130/131, then 183 Config and 132 Back). xi-tools reads these numbers as text ids with a missing string table; they are shape references, the same mechanism as the in-game `windowps` labels.
- **Not in these files:** the client-composed content (character names in the bars, the details text, name-entry text, the preview model, which is an ordinary PC model built from race, face and equipment), the title segment picker and any zone-loading art.

## Lobby text

`LobbyTextTables` reads the lobby's text from the retail DATs; nothing is copied into the client. Rows read 2026-10-04 (`LobbyResourceTests` checks the ones used).

- **`ROM/165/71`** (`XISTRING`, English; `XiStringTable`: count at 0x24, 12-byte index entries from 0x38, NUL-terminated CP932 strings; `ROM/97/36` is an older copy, the one XiPackets names). Rows used: 6-10 the status lines ("Acquiring player data.", "Acquiring character list.", "Notifying lobby server of choice."), 22-24 the creation checks, 28 "Deleting from Lobby Server.", 29/30, 40/41, 51/52 the nations' titles and descriptions, 99-102 the title menu's help lines, 104 / 105 the list's ("Select a character to play." / "...to delete. Deleted characters cannot be restored."), 106-112 the creation steps', 139 / 140 / 216 the rename prompt, 172 "The data will be lost forever. Proceed?", 173 / 174 "Register "%s" / and begin play?", 196 "You cannot create any more characters.", 229 "Select cancel to terminate the deletion process.".
- **`ROM/165/70`** (`d_msg`, English): the error messages. Row 1 is "Error code: FFXI-%04d"; the others are in the order of XiPackets' error list but not one row per code (3117 has none), so `LobbyTextTables` maps the codes it knows (LSB's 201, 208, 305, 313, 314, 321, 331, 332 and others) to rows by matching the text. An error shows its message lines and then the code line ("Error code: FFXI-3313"); **unverified** that retail shows both.

## Screens and input (`LobbyController`)

`LobbyController` (Core `Ui/Lobby/`) is the lobby's state machine; `StockUiLobby` and `LobbyFrameRenderer` (App) draw it.

- **Licence page:** before the title menu the lobby shows `ptc8lice` (Accept / Decline, `lobbywin` #101 / #102) with `ROM/165/71` row 158, the notice about the User Agreement and Rules of Conduct, over the title art without the title buttons. Accept (the default) shows the title menu; Decline (or Cancel) leaves the lobby. It shows once per launch. Confirmed as the page retail shows by the maintainer's screenshot (image-8, round 2); its look is described under Drawing.
- **Title menu:** `loby2win` over `loby1win`; the cursor follows the buttons' authored links (wrapping). Select Character and Delete Character open the list (nothing happens without a character), Create Character starts creation ([#33](https://github.com/jimmy58663/GordianXI/issues/33)), Back leaves the lobby; Config does nothing yet (`lobycwin` is not built). Cancel does nothing here (retail behaviour not checked).
- **Character list:** `dbnamese` over `bgnamese`; the cursor skips free slots (LSB fills them with a one-space name) and starts on the first character. Each bar shows the name (yellow when the character must be renamed, the star when a race change is available). The selected character stands in the preview, with its name and job / level under the logo. Confirm plays the character: a `ptc2warn` status window with row 10 while 0x07 / 0xA2 run, then the ticket goes to the launcher. Cancel returns to the title menu.
- **Errors:** a refused request shows its text in `ptc5ok`; after OK the list is back, unless the server dropped the connection, in which case the lobby closes.
- **Keys:** arrows and keypad 8 / 2 / 4 / 6 move, Enter / keypad 5 confirm, Escape cancels (`ViewportWindow.HandleLobbyKey`). Every key goes to the lobby while it is open. **Mouse:** hovering a button of the window taking input moves the cursor there, a left click activates it, a right click cancels (`StockUiLobby.HitTest`). Gamepad: **not wired.**
- **Help bar:** the selected title button's or the screen's line from `ROM/165/71`.

## Drawing (`StockUiLobby`, `LobbyFrameRenderer`)

- **Layout spaces.** The lobby menus are authored in three spaces: 1024 x 768 (`loby1win`, `loby2win`), 640 x 480 (`bgnamese`, `dbnamese`, `dbaccwin`, `hnbackwi`, `ptcbgwin`, `lobyhelp`) and the in-game 512 x 448 with anchors (the rest). All are fitted into one 4:3 rectangle centred on the viewport (pillarboxed on wide screens) and scaled to its height; the prompts (frame x 256) are centred on it; the help bar spans the 4:3 width at its authored distance from the bottom of the 448 space, below the title's copyright line. **Unverified against retail** (how retail scales the lobby on wide screens is not captured).
- **Window size.** The lobby is laid out against the viewport's rendering surface (`_deviceManager.CurrentWidth` / `CurrentHeight`), which is the window's client area in physical pixels: the 3D scene renders at the same size today. The backdrops' tiled `newtex` fill (`loby1win`, `bgnamese`) is stretched over the whole window and the help bar spans its full width, so wide or tall windows show no bars; the art, windows and preview stay in the 4:3 area. If the scene resolution is ever decoupled from the window, the lobby must keep using the surface (window) size.
- **Frame order.** A black clear, the screen background (`loby1win` or `bgnamese`), the preview model (the entity renderer alone, no zone), then the windows, text, prompt and cursor. The two UI passes use separate `StockUiRenderer`s. The client's in-game window border lines are left out (`DrawMenu(..., border: false)`). Selected buttons use their kind-4 image where they have one (title), else the menus' orange tint (prompts); the `anc_s` cursor sits beside the selected button.
- **Preview (`LobbyPreview`).** One player entity at the origin of its own `WorldState`, `GrapIDTbl[0]` = `(race << 8) | face` and the 0x20 list's gear (normalized to the world packets' slot bits), facing the camera (heading byte 192). The camera looks along -Z with a 30° field of view, placed so the feet land at 640-space y 372 and 2.4 yalms above them at y 160, centred at x 150 (the left part of the list screen). It stands in the normal player idle (the entity carries 100 % HP: with the default 0 % the animation classifier picked the death pose, the round-1 in-game bug). **Unverified against retail:** the model's place, scale and facing, and whether retail turns it; character size (small / medium / large) is not applied to the model scale anywhere yet.
- **Licence page (matched to retail, image-8, 2559 x 1439, 2026-10-05).** Unlike the other screens it is drawn the way retail draws it at that size: the `ptcbgwin` backdrop (`lobbywin` #85: its 640 x 480 image, though the frame says 640 x 240) stretched non-uniformly over the whole window, logo included (4x wide, 3x tall at 2559 x 1439), its two fill halves drawn with their top and bottom corner colours swapped and opaque (retail is bright at the window's top and bottom edges and dark in the middle; the pixel values then match); the `ptc8lice` window at one screen pixel per layout pixel in a 512 x 448 box centred on the window (its frame (256, 128) puts it at (1280, 624)), with the client's border lines; the text in the upright log font (`StockUiLogFont`, colour 0x80 grey, not the menus' italic font), left-aligned 28 px in, from 13 px down, 16 px apart; the empty `lobyhelp` bar at 1:1 its authored 69 px above the bottom, across the full width, marked by the border lines at its top and bottom (26 px apart). Every element of image-8 comes from a DAT asset; none is missing. Verified offscreen (`LobbyRenderTests.RendersLicencePageLikeRetail`, `lobby_licence_1440.png`) against image-8's pixels. How retail lays out the other lobby screens at this size is not captured; they keep the 4:3 fit above.
- Verified offscreen on D3D11 (`LobbyRenderTests.RendersTitleMenuCharacterListAndPreview`, writes `lobby_*.png` with `GORDIAN_UI_DUMP`): the title art and buttons, the list with names and the star, a Hume female and a Mithra standing in the preview, the status window.
